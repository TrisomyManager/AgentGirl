# 参考宿主的账号与数据控制

本页描述统一 `main:app` 的单进程部署。独立启动业务模块的应用需要宿主自行安装访问边界；当前实现没有分布式会话或多 worker 删除锁。默认聊天、摘要、向量与豆包语音配置保持不变。

## 本机使用与账号模式

未设置 `COMPANION_ACCESS_CONFIG_FILE` 时，仅接受 loopback 来源。浏览器 Origin 必须在 CORS 列表中，Host 也必须是本机地址；代理转发头不会获得本机信任。默认设置适用于本机开发，反向代理或远程客户端应使用账号模式。

在 `apps/backend` 中生成账号：

```powershell
.venv/Scripts/python.exe tools/manage_access.py --user-id alice --output companion_access_credentials_alice.json
.venv/Scripts/python.exe tools/manage_access.py --user-id operator --role admin --output companion_access_credentials_operator.json
```

工具向私有凭据文件写入随机访问密钥，只向 `companion_access_config.json` 写入 SHA256。Windows 文件撤销继承授权后仅授予当前用户访问，POSIX 使用 0600。输出文件必须不存在；为同一个 user_id 再次运行会轮换该账号的密钥。不要把凭据文件、环境文件、运行配置或数据库加入版本控制。

设置 `COMPANION_ACCESS_CONFIG_FILE=companion_access_config.json` 后重启宿主。凭据文件由管理员在可信渠道分别交付给对应用户。远程部署使用 HTTPS/WSS；持有密钥即代表该身份。PC 宿主初始注册可通过 `XIAONUAN_ACCESS_KEY` 提供账号密钥，设备取得自己的 token 后继续使用设备协议。

登录后浏览器只在 sessionStorage 保存随机会话凭据，不保存原始访问密钥。会话最多八小时，服务端重启后失效。账号设置变化、删除密钥、角色变更及登出会撤销相应会话，并关闭仍在进行的 HTTP/SSE/通话；浏览器普通用户看不到模型、语音及调试管理入口。

管理员是可信的宿主维护者，能够修改模型、插件配置并运行原始图查询，不能把管理员视为无法访问其他用户数据的角色。本机模式同样属于可信管理员环境。

## 协议

| 接口 | 用途 |
| --- | --- |
| `GET /access/status` | 查询模式与当前会话，不缓存 |
| `POST /access/login` | `{ "access_key": "用户在自己终端获得的密钥" }`，返回随机 session_token |
| `POST /access/logout` | 撤销当前随机会话 |
| `GET /privacy/user/{user_id}/export` | 下载当前账号的数据 JSON，不缓存 |
| `GET /privacy/user/{user_id}/status` | 查询清理 receipt 与待重试资源，不返回文件列表或内容 |
| `POST /privacy/user/{user_id}/erase` | `{ "confirmation": "删除我的全部数据" }`，首次清理或重试未完成清理 |

HTTP 使用 `Authorization: Bearer <session_token>`，SDK/受信设备注册也可使用宿主访问密钥。用户不能通过请求体、路径、查询、会话 ID 或资源 UUID 访问其他账号。未知归属的旧会话不能被新账号接管。内部 HTTP 组合使用仅在进程中传递的对象能力，网络 header 不能伪造。

实时语音的 WebSocket 子协议为 `['companion.session', session_token]`，设备为 `['companion.device', device_token]`；URL 不携带凭据。通话身份/会话在握手后固定。音频文件按账号登记，浏览器带授权获取后播放临时 blob，结束或停止时释放。账号模式无法读取未登记归属的旧音频，需重新生成。

## 数据范围与清理顺序

导出包含当前用户的记忆原文/状态/本地图关系、原始会话与可归属摘要、日总结、画像、偏好、人格/关系状态与观察记录、提醒、推送、任务及步骤、语音文件元数据，以及已启动设备网关中的设备/命令/审计。向量系数、访问凭据、模型配置和其他账号不在其中。单表上限十万行，整个文件上限 50 MiB；超限明确失败，不交付截断文件。

删除先阻止新请求并取消、等待该用户的聊天、通话、任务、插件调用和后台写回。旧上下文会继承无效代次，无法在取消后恢复 SQL 写入。拒绝取消的工作使删除返回 409，保留阻止新工作状态，任务真正结束后才可重试。设备/提醒后台操作同样加入所有权边界，不中断其他用户的公共调度器。

SQL 事务一并删除个人内容并提高记忆版本，保存待清理资源 receipt。随后清理本地缓存、推送队列、已登记语音文件和设备网关；非 Lite 模式另清理已启用的外部图。多个旧用户混在同一会话时，删除相关派生摘要并保留其他用户的原始回合，重新计算摘要。仅有所有权、没有回合的空会话也会清理。

文件权限错误、外部存储不可用或旧图中存在无法归属的共享节点时，返回 **202/pending**，并在数据库保存待重试资源。期间拒绝新的用户内容写入，重启后仍生效。设置页提供重试入口；只有全部清理完成才返回 **200/completed**。完成后 receipt 不再保存待删除文件名或会话列表，只保留账号 ID、作业 ID、状态和时间；管理员配置的账号身份/密钥不因清理内容而被删除。

前端在清理前停止输出、录音、识别回调和通话；成功或进入待重试后移除当前浏览器的账号缓存，并通知同源其他标签。登录/刷新先核对最新清理 receipt，避免清理已提交但响应丢失时再次展示旧缓存。完成后可重新开始新的对话。

“清空本机聊天显示”只移除当前浏览器的显示记录。宿主备份、其他浏览器的离线缓存、AI 服务商保留记录、插件自行保存的数据及已经执行的第三方操作结果需要各自处理。删除不能撤销已完成的外部操作，也不承诺安全擦除 SQLite 已释放磁盘块或历史备份。

## 验证范围

V2.25：PostgreSQL及Neo4j实际隔离验收已通过，详见production-storage.md、neo4j-ownership.md。图清理会保留不含对话内容的最小防重放回执：单删记录来源标记，整库清理保留摘要化账号键和代次，防止迟到工作恢复已删内容。原始图事实与属性均移除；宿主备份和管理员配置身份仍按上述范围单独处理。

自动回归覆盖身份/资源隔离、会话抢占竞态、撤销活动 SSE/WS、请求大小、删除等待、旧派生写入拦截、失败清理的持久化重试、账号缓存与迟到响应、麦克风取消、导出和设置交互。测试数据库独立于本地应用数据。

真实隔离实例已验证方舟聊天、豆包 TTS（两次分别 16,749 / 16,941 字节）、受保护音频、原生 O2 的会话鉴权和登出断开，以及浏览器登录/切换账号/导出/删除。额外验证了真实删除事务提交后主动丢弃 HTTP 响应，刷新先核对 receipt、清除旧缓存再展示应用。生产 PostgreSQL、Redis、Neo4j 的实例验收仍归执行表的 2.1/2.3 与部署项目；旧图的所有权隔离已在代码中补齐，旧共享节点不会自动猜测归属。
