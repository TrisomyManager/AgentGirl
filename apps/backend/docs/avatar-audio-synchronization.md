# 表情、动作与音频同步（5.3 / 8.4）

2026-10-20：后端 `avatar_runtime` 组装版本 1 的 `AvatarTimeline`；TypeScript `packages/avatar-runtime` 提供独立播放时钟、时间轴校验、音频能量计算和语义映射。二者都没有参考应用、语音厂商和渲染器依赖。参考宿主在普通语音、SSE 每段语音和实时通话中注入/转发公开时间轴，内部人格/记忆状态不发往客户端。

时间轴包含 turn_id、segment_seq、可空 duration_ms、音频播放时钟、最多 32 个表情/轻动作 cue。未知时长保持为空，不能按字数冒充准确的音频时间。浏览器以 HTMLAudioElement.currentTime 或 AudioContext.currentTime 驱动呈现，依据实际音频 RMS 控制口型开合。收到 metadata 不代表已经发声；暂停、卡顿、自然结束、打断、挂断和播放器失败均关闭口型。播放代次拒绝旧音频的帧或清理回调。异步解码绑定接收该音频时的时间轴，后到句子的表情不能覆盖尚未播放的前一句。

Live2D 适配器使用现有资产 f01–f04 和可用 motion，覆盖温柔、关心、恐惧、厌恶等情绪，限制动作频率。表情沿用资产淡入淡出；嘴形和轻微头部偏移平滑过渡。口型参数在引擎 `beforeModelUpdate` 阶段写入，避免被 idle motion 覆盖；卸载会移除监听。遵循系统减少动态效果的偏好。通话面板也显示实际模型。

原生豆包的情绪时间轴仍来自会话启动快照，当前用户转写的反应在完整回合提交时更新，不能宣称每句都经宿主独立情绪分类。链式 cloud/local 则使用本轮生成前准备的上下文。修复 O2 的空/缺失句子文字事件：在首个实际音频字节之前确保宣布播放格式与时间轴，不再因句子文字缺失而令浏览器拒收真实音频。

边界：RMS 是音量驱动的开合，不是音素/发音对齐、表情捕捉或 audio2face；3D/外部呈现服务仍属 8.6。音量分析不可用时保留语音播放、闭嘴降级。没有新增 avatar HTTP 会话服务，旧提案接口仍是后续设计。
