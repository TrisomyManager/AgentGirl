# 实时通话的人格与记忆连续性（5.1 / V2.12）

2026-10-19：用户恢复开发后完成。默认继续使用原生豆包实时通道与既有模型配置，不改变声音配置文件。

## 边界与生命周期

- `voice_layer/conversation_context.py` 仅定义上下文载体与可注入 loader；业务模块不导入宿主。独立使用时不配置 loader 可沿用通用语音提示。
- `core_orchestrator/runtime_hooks.py` 组装用户身份、角色选择、记忆、情绪和关系，复用文字端的召回及反应服务。上下文准备总等待 5 秒；宿主已配置而读取失败会明确报错，不静默换为通用人格。跨用户复用已有会话会被拒绝；这不替代后续统一认证。
- cloud/local 每轮 ASR 后准备上下文及反应，再生成语音。原生豆包会话在建连时注入人格/记忆快照，内部模型继续处理对话；宿主在收到真实转写后，于完整回合提交时分类并原子更新情绪与关系。不能宣称宿主分类在原生模型当前回复前完成。
- 原生文本结束与音频结束均已到达、并实际发送过音频才持久化；两种结束顺序均支持，重复结束事件不重复提交。打断、失败、空音频及不完整回合不会保存成完整回复。
- 统一生成 turn_id 并沿用 SQL 幂等观察。语音写回按用户/会话排队；后续文字（普通/SSE）和 chained 语音准备上下文时等待相同会话的已完成写回，不阻塞其他用户。
- 原生通道不能在保留供应商历史时重绑定用户/会话，需重新连接。当前语音 provider 没有工具执行器，提示词明确不宣称已执行提醒/设备操作。
- `turn_done` 表示供应商生成/发送完成，不表示浏览器已经播放完毕。精确已听范围、途中用户消息提交和音频/表情时间轴仍是后续工作。

## 数据清空和 SQLite

- 普通后台提取在排队前捕获数据版本；直接写入在向量生成前捕获版本，落库时与版本锁在同一事务中核对。清空过程中在途提取、排队任务、在途 embedding 均无法恢复旧 SQL 记忆。新版本写入仍可成功。
- Dream 的既有版本校验保留。生产 PostgreSQL/外部 Neo4j 的联调及跨存储原子性仍待验，不把该修复等同 7.3 完整隐私控制。
- SQLite 连接创建、在途查询、关闭均需等待 worker 完成后传播取消，关闭等待线程退出。宿主排空任务并释放连接池后回收遗留连接；测试同样在各事件循环退出前清理。没有屏蔽线程警告。

## 实际验证

- 隔离临时数据库和独立合成用户，真实 TTS 将问题转为 PCM，再进入默认原生实时服务。原生回复正确引用此前文字约定；真实 ASR 收到用户新城市，返回 555002 字节音频，完整语音回合写入 SQL；清除工作记忆缓存后仍读到两轮历史，关系增加一次。
- 随后的真实文字聊天正确回答通话中刚说过的城市。发现并修复近期对话追问被长期记忆列表覆盖的问题；普通与 SSE 共用修复入口。
- 该单次真实服务验证证明本场景接线，不代表任意网络下的可用率、主观语气评分或延迟 SLO。结果位于忽略目录 `output/qa/voice-continuity-result.json`；QA 使用应用 lifespan 自动关闭服务资源。
