## 每条记忆的独立证据

参考管线将每条SQL记忆投影成不可变的`MemoryEvidence`与`MemoryFact`，提取到的实体通过用户独立的`MemoryEntity`关联。重复写入同一来源只能保留同一摘要；同名实体的新旧偏好不会合并属性，也不会把新值借用旧来源。

召回只接收当前SQL检索得到且仍有效的来源ID，外部查询结束后再检查删除、淡化和清空代次；本地图事实也保留来源直到响应组装。迟到结果不能恢复已删事实、画像摘要或已清空的会话摘要。已验收的精确线索再激活与用户显式恢复保留。

单条删除和整库清理都先在SQL提交清理记录，再执行外部删除。单条删除只移除其事实，其他来源仍使用的实体保留。按用户轮转的后台任务每5秒尝试一批用户，每用户一次最多32条单删记录；失败保留，取消先等待工作退出再关闭资源。启动恢复和新进程重启均已验证。

Neo4j事务另保留最小防重放记录：单删留下不含正文的来源删除标记；整库清理留下仅含用户摘要键、代次和清理代次的`GraphFence`。重复旧清理不会删掉新一代事实，迟到旧写入会在图服务器拒绝。它们是删除回执，不保留记忆正文；整库清理会移除单删来源标记，摘要键回执继续用于阻止旧工作。

旧图的手工/迁移事实没有SQL证据时不会进入参考宿主回复；低层SDK仍可读取和导出。不会猜测旧来源或从共享属性补造证据。SQL及本地图仍是主存；可选图投影失败或在清理期间跳过时不承诺全量自动回填。多worker协调仍需分布式机制。

## 当前实现

Neo4j 是可选适配器，SQL 与本地实体关系索引保持可用。实体、偏好、事件与情绪按用户保存，嵌套属性用JSON保存；事件外部ID同样参与用户命名空间。邻域深度明确支持1或2，不能跨用户走第二跳。失败连接会关闭驱动，关闭后清掉引用；模块启动失败也进入资源清理。

参考宿主的提取写图与“清空全部”共用按用户的进程内锁。SQL清空同时保存外部图清理记录，成功删除Neo4j数据后才移除记录；故障或取消不假报完成。待清理时不将旧图事实加入回复，隐私导出显示待清理，新的图写入也暂时跳过。旧回合必须匹配SQL记忆代次，避免清空后恢复旧图。

Web会显示“外部关联信息仍待清理”，刷新从摘要接口恢复状态，完成后会显示已清理；切换账号丢弃旧删除响应。这里不宣称多worker分布式隔离、无限量后台恢复或SQL/Neo4j跨库原子提交。独立SDK写入应由其宿主管理代次与并发。

## 旧图迁移

停止写入后，通过宿主环境设置Neo4j连接参数。在源码或已安装wheel环境使用：

```text
python -m memory_system.graph_migration
python -m memory_system.graph_migration --export-review PRIVATE_REVIEW_PATH
python -m memory_system.graph_migration --review PRIVATE_REVIEW_PATH --apply --backup PRIVATE_BACKUP_PATH
```

默认只输出节点/关系数量。审阅文件包含原始节点、属性及所有者，必须保存在宿主私有目录；建议用`companion_graph_migration*.json`命名（已忽略）。备份和审阅文件独占新建，不覆盖原文件。Windows下目录访问权限仍由宿主设置。

单一可证明所有者的旧节点保留原属性并转换为用户命名空间。共享节点的`properties_by_user`必须逐用户填写；共享关系也必须明确逐用户属性，不会把被合并的私有属性复制给所有账号。无法确定所有者的孤立节点、未支持的标签、已存在的目标身份、过时审阅和异常关系类型均拒绝自动转换。

应用先写私有档案，再在单笔Neo4j事务中锁定源节点、重新验证快照、建立用户节点/关系并移除旧节点。失败整笔回滚；无旧节点时可重复执行。默认处理上限1000节点、10000关系、10MiB档案，超过上限需要离线分区方案。档案保留时间类型标识供人工恢复，不声称提供一键恢复工具。
