## 4. 模块级优化建议

### 4.1 core_orchestrator / 编排层

| 现状 | 建议 | 理由 |
|------|------|------|
| LangGraph 状态机 | 保持 LangGraph 主线 | 调研确认最适合有状态对话编排 |
| 无中断处理 | 加入 barge-in 机制参考 OpenTalking | 实时语音场景需要话语级中断 |
| project_status 面板 | 增加时序打点（TTFT/TTS首块/总延迟） | 可观测性提升 |

### 4.2 memory_system / 记忆系统

| 现状 | 建议 | 理由 |
|------|------|------|
| 5阶段管线 | 引入 mem_id 命名空间 + search-before-upsert | Bailongma 方案更可控 |
| bag-of-words working memory | 替换为 LLM 摘要器 | PROJECT_PLAN P2 任务 |
| 简单去重 | LLM 识别器 tool calling 模式 | 语义去重优于字符串匹配 |
| pgvector 主线 | 保持，中期加入 Neo4j 图谱 | ADR-003/005 已验证 |
| — | 追踪 Letta 结构化记忆层级 | 调研确认 Letta 领先 Mem0 |

### 4.3 voice_layer / 语音层

| 现状 | 建议 | 理由 |
|------|------|------|
| 字符串 provider 分发 | Protocol 注入 | 更规范的 provider 模式 |
| 无 TTS 回退 | 加入 fallback 链：Fish Audio→CosyVoice→Edge TTS | OpenTalking 已验证 |
| ASR: whisper.cpp + faster-whisper | 评测 sherpa-onnx 补充 | <50ms 端侧延迟 |
| TTS: Fish Audio S2 主线 | 评测 ChatTTS + CosyVoice + GPT-SoVITS 补充 | 多场景覆盖 |

### 4.4 action_executor / 行动层

| 现状 | 建议 | 理由 |
|------|------|------|
| 5个内置 handler | 保持，待主动性模块稳定后扩展 | PROJECT_PLAN 策略 |
| ActionRegistry 装饰器 | 统一到全局能力注册表 | OpenTalking registry 模式 |
| 无自主循环 | 引入 TICK 机制（Bailongma Module 2） | 主动性核心 |

### 4.5 persona_engine / 人格层

| 现状 | 建议 | 理由 |
|------|------|------|
| PAD + Big Five + YAML | 保持，长期追踪 PersLLM 参数嵌入 | 调研确认方向正确 |
| 基本情绪状态机 | 参考 Soul of Waifu 28情绪→表情映射 | 丰富度提升 |
| OOC 检测 | 集成 NeMo Guardrails 作为对话护栏 | 安全层增强 |

### 4.6 前端渲染 / Web + PC Client

| 现状 | 建议 | 理由 |
|------|------|------|
| pixi-live2d-display | 保持 | 调研确认最佳开源选择 |
| Live2D 空闲动画 | 参考 OpenTalking 空闲帧生成+缓存 | 防止画面冻结 |
| 桌面窗口 | 引入透明背景+置顶+穿透 | Open-LLM-VTuber 已验证 |

### 4.7 工程质量

| 现状 | 建议 | 理由 |

## 5. 与 OpenTalking 的融合建议

经过对比分析，两项目定位互补而非竞争：

| OpenTalking 优势 | AgentGril 整合方式 |
|-----------------|-------------------|
| 视频数字人实时推流 | 如需要视频渲染→引入 aiortc WebRTC 管线 |
| 多模型后端适配 | 引入统一 registry 模式，配置驱动切换 |
| 工程质量工具链 | 直接引入 ruff+mypy+Loguru |
| TTS fallback 链 | voice_layer 加入 |
| 时序打点 | project_status 面板扩展 |

**不建议**将 OpenTalking 作为 AgentGril 的替代或主干——AgentGril 的记忆/人格/设备协调是独特优势，OpenTalking 是管线层面的有益补充。
